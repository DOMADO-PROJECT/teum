스크립트·외부 이미지·외부 폰트 요청은 없습니다.<br><br>

Hero는 홈페이지의 심벌 형태·입체 질감과 인트로 동작을 재사용합니다.<br>
화면 중앙의 심벌이 눌리며 작아졌다가 크게 퍼지고, 열린 틈 사이로 브랜드명·확정 슬로건·서비스 설명 한 줄이 드러납니다.<br>
3초 인트로를 한 번 재생한 뒤 완성 화면을 유지합니다.<br>
모바일에서는 심벌과 문구를 세로로 배치하고, 모션 감소 설정에서는 완성 상태를 바로 표시합니다.<br><br>

흐름·아키텍처 도식의 텍스트와 연결선은 정적으로 읽을 수 있습니다.<br>
사용 흐름 도식은 단계 순서를, 아키텍처 도식은 데이터 이동 방향을 보여줍니다.<br>
이 움직임은 실행 시간이나 실제 진행률을 표현하지 않습니다.<br><br>

아키텍처는 요청·접수 → GitHub 수집·입력 보관 → 규칙 분석·의존성 추출 → OSV 조회 → 자체 코드 흐름 분석 → 결과 저장 → 선택 AI 검토·저장 → 결과 조회 순서로 선을 채웁니다.<br>
수집과 분석은 별도 Workflow이며, OSV와 OpenAI는 Sandbox 밖에서 각각 호출합니다.<br>
두 외부 서비스를 별도 카드로 나누고 전송하는 정보와 AI 동의 조건을 표시했습니다.<br>
모션은 자체 코드 흐름 분석과 AI 검토를 사용하는 한 경로의 예시입니다.<br>
시작 요청의 접수 응답과 결과 조회를 구분하며, 실제 접수·실행의 겹침이나 모든 재시도·정리·분기를 재현하지는 않습니다.<br><br>

모션 감소 설정에서는 움직이는 장식을 멈추거나 숨깁니다.<br>
이미지가 작게 보이면 원본 SVG 링크를 열어 확대할 수 있습니다.<br><br>

사용 흐름은 단계명과 핵심 설명 한 줄로 정리하고, AI의 별도 동의와 재점검의 비교 조건을 남겼습니다.<br>
가로형은 단계명과 설명을 나란히, 모바일형은 설명을 아래에 배치합니다.<br>
두 형식은 같은 내용을 표시합니다.<br>
번호는 테두리 없이 표시하고, 옅고 가는 보조선으로 순서를 연결합니다.<br>
강조된 번호에서 다음 번호로 가는 선을 위에서 아래로 파랗게 채우고, 도착하면 다음 번호로 강조를 넘깁니다.<br>
파란 흐름선은 두께 `2`, 회색 보조선은 `0.8`로 표시합니다.<br>
글자의 위치는 고정한 채 1.5초 간격으로 네 단계를 잇는 6초 주기이며, 모션 감소 설정에서는 정적으로 표시합니다.<br><br>

ERD는 2026-10-27 작성했으며, 2026-10-30 실제 PostgreSQL 카탈로그를 읽기 전용으로 다시 조회해 대조했습니다.<br>
`public` 테이블은 총 16개이며, 과거 웹사이트 점검용 `website_targets`를 제외한 15개와 `auth.users` 참조를 표시했습니다.<br>
주요 키·자료형과 자기 참조를 포함한 외래키 19개를 연결했습니다.<br>
각 테이블 이름 아래에 역할을 한글 한 줄로 설명했습니다.<br>
오른쪽 위에는 DB 종류인 `PostgreSQL`을 표시합니다.<br><br>

`PK`는 기본키, `FK`는 외래키, `PK/FK`는 두 역할을 겸하는 컬럼입니다.<br>
여러 컬럼에 `PK`가 표시되면 함께 복합 기본키를 이룹니다.<br>
키 표시는 같은 열에 정렬했습니다.<br>
테이블은 외곽선 없이 헤더 배경·옅은 행 구분선·은은한 그림자로 묶었습니다.<br>
모든 관계선과 끝 기호는 같은 진한 회색과 두께를 사용하며, 색상으로 관계의 종류나 중요도를 구분하지 않습니다.<br><br>

[MySQL Workbench 표기법](https://dev.mysql.com/doc/workbench/en/wb-relationship-tools.html)에 따라 식별 관계 5개는 실선, 비식별 관계 14개는 파선으로 표시합니다.<br>
끝 기호는 실선으로 유지합니다.<br>
[Workbench 8.0의 판정 기준](https://github.com/mysql/mysql-workbench/blob/8.0/plugins/db.mysql.editors/backend/mysql_relationship_editor.cpp#L258)대로 외래키의 모든 컬럼이 자식 기본키에 포함되어야 식별 관계입니다.<br>
그림에서 생략한 복합 외래키 컬럼도 포함해 판정했으므로, 일부 컬럼만 `PK/FK`인 관계는 파선입니다.<br>
관계선 양끝의 Crow’s Foot 기호는 막대가 하나, 원이 선택, 갈래가 여러 개를 뜻합니다.<br>
NULL 허용과 기본키·UNIQUE 제약을 대조해 선택 여부와 개수를 표시했습니다.<br><br>

`scan_runs.baseline_id`의 자기 참조도 선으로 표시했습니다.<br>
일부 외래키 13개, 공통 `workspace_id` 등 일부 복합 외래키 컬럼, 전체 컬럼·private 및 Auth 내부 구조는 생략했습니다.<br>
`uploads`는 현재 GitHub 수집 입력의 보관 기록으로 사용합니다.<br>
`workspace_members`의 현재 역할은 소유자만 지원합니다.<br>
이 도식을 팀 초대나 여러 권한 등급의 구현으로 해석하지 않습니다.<br>
실제 사용자·분석 내용·운영 설정은 포함하지 않았습니다.<br>
정적 SVG이므로 DB 구조 변경 시 다시 대조해야 합니다.<br><br>

SDK 그래프는 고정한 자사 코드 26개 파일·2,277줄의 실행 기록으로 만들었습니다.<br>
각 지표에서 r5를 100으로 놓았으며 파란 막대는 r14/r15의 평균을 나타냅니다.<br>
시간은 기록된 전체 실행 시간을 분·초로 표시하고 비용은 usage 기반 추정치입니다.<br>
표시값은 반올림하며 절감률과 막대 길이는 반올림 전 원값으로 계산했습니다.<br>
가로형과 세로형 SVG는 같은 값을 표시합니다.<br>
기준·개선 후 수치와 감소율은 처음부터 고정해 읽을 수 있습니다.<br>
막대만 약 2.2초 안에 최종 비율로 줄어든 뒤 오래 머물며, 12초 주기로 반복합니다.<br>
움직이는 중간 길이는 관측치가 아닙니다.<br>
모션 감소 설정에서는 최종값만 표시합니다.<br><br>

## 03. 도식 디자인 기준

2026-10-27 확정한 [ERD](../assets/diagrams/database.svg)와 [서비스 아키텍처](../assets/diagrams/architecture.svg)를 이후 도식 개선의 기준으로 삼습니다.<br><br>

- **목적에 맞게 정보를 줄입니다.**<br>
  설명용 도식은 구성 요소·관계·흐름을 우선하고, 역할 설명은 짧은 한글로 씁니다.<br>
  첫 화면인 Hero는 브랜드명·확정 슬로건·설명 한 줄과 심벌에 집중합니다.<br>
  상세 수치와 긴 설명은 본문에 둡니다.<br>
- **색상과 글자 계층을 유지합니다.**<br>
  흰 바탕, 본문 `#191f28`, 보조 글자 `#566270`, 강조색 `#1d65d1`, 옅은 헤더 `#edf4ff`를 사용합니다.<br>
  상단에는 `teum.`과 작은 도식 제목을 둡니다.<br>
- **카드는 테두리 없이 묶습니다.**<br>
  헤더 배경과 은은한 그림자만 사용합니다.<br>
  그림자는 `dy=2`, `stdDeviation=2`, `#191f28`의 불투명도 `0.06`이 기준입니다.<br>
- **연결선은 역할에 맞게 배치합니다.**<br>
  ERD·아키텍처의 관계선과 끝 기호는 `#4b5563`, 두께 `1.8`을 기준으로 합니다.<br>
  사용 흐름의 순서 안내선은 `#d8dfe6`, 두께 `0.8`로 가볍게 표시하고, 번호에는 원형 테두리나 채움을 넣지 않습니다.<br>
  글자·카드·다른 선을 가로지르지 않도록 여백을 확보하고, 실선·파선에는 명확한 의미를 부여합니다.<br>
- **모션은 데이터 흐름을 설명합니다.**<br>
  파란 강조가 이동 방향과 처리 순서를 따라가게 하고, 실제로 순차적인 작업을 동시에 움직이지 않습니다.<br>
  정지 상태에서도 연결이 읽혀야 하며 모션 감소 설정을 지원합니다.<br>
  아키텍처의 20초 주기는 설명용이며 실제 소요 시간이 아닙니다.<br>
- **실제 표시 크기에서 비교합니다.**<br>
  전·후 미리보기와 README 크기·모바일 축소 화면에서 글자, 여백, 선의 겹침을 확인합니다.<br>
  도식마다 필요한 정보량에 맞춰 글자 크기를 조정합니다.<br><br>
